# FBZ 插件平台扩展 · 2026-10-05

插件 ZIP 可独立声明后台菜单、包内管理页面、允许的页面动作、配置、事件、定时任务和存储源。后台只展示已审批且启用的插件菜单；启停或升级后，菜单在当前页面即时刷新。

包内管理页由 FBZ 从当前活动包读取，放入无同源权限的 sandbox iframe。页面通过 `postMessage` 请求清单声明的动作；宿主与后端核查 iframe 来源、管理员身份、当前安装包、启用状态、动作声明和 HTTP 签名。插件页面拿不到管理员令牌，不能直接调用 FBZ API 或外部网址。通用的存储账号、扫码、虚拟挂载与媒体库绑定仍由宿主提供，并按 provider ID 隔离；插件处理目录、认证与播放地址。非扫码账号可使用 `storage.accounts`、`storage.createAccount` 和 `storage.connect` 声明自己的表单。

## 光鸭

`fbz-api/plugins/guangya-storage` 含 `manifest.json`、`ui/index.html` 和 Node HTTP 服务。包由仓库现有 `scripts/package-plugin.ps1` 生成，在插件市场或手动安装界面上传，经已有签名审核、批准、启用后侧边栏显示“光鸭网盘”。Node 服务验证签名再处理存储请求。旧账号仍走旧接口，管理员可在新插件页执行“接管旧账号”；仅更换账号 provider 标识，保留密文、媒体库、媒体条目及进度。停用新插件后，宿主拒绝其新的账号和播放地址请求。

外部 HTTP 进程按既有插件模型独立运行，安装 ZIP 不自动执行包内 Node 代码。部署需让 FBZ 与插件配置相同 `PLUGIN_SECRET_KEY`，允许插件主机，并启动该服务。跨容器地址可设置 `FBZ_PLUGIN_HTTP_ENDPOINT_OVERRIDES` JSON 映射，调用时仍检查主机 allowlist。生产包仍需可信签名，不能省略管理员批准。

## 验证边界

- 前端 54 项测试、类型检查和生产构建通过；Node provider、签名验证和实际本地 HTTP 动作测试通过。
- Rust 1,221 项常规测试通过，51 项需外部条件的测试默认忽略；另在隔离数据库执行光鸭包安装、审批、启用、页面读取、菜单出现与停用隐藏。迁移 0100 保留了 3 个历史账号与库关联，允许新的 provider ID。安装隔离测试走 repository 层，不等同于生产签名安装与浏览器实机验收。
- 未替换正在运行的主 API，未对真实账号自动接管。生产签名私钥、部署时外部 HTTP 进程与浏览器扫码播放需在新版本部署后验证。
